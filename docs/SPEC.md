# MILDO OS — 구현 명세 (모듈 빌더용)

MILDO OS는 프로그레스미디어가 「수면밀도 2027 퍼포먼스 마케팅 제안」(2026.11, v3)에서 약속한 **수면밀도 전용 운영 프로그램**을 실제로 동작하는 웹 앱으로 구현한 것이다. 경쟁 PT(26.11.19~20)의 **라이브 데모 15분**(제안서 부록 p.60)과 RFP 필수 제출물 「대시보드 · 자동 알림 실제 화면, 리포트 샘플」에 그대로 쓰인다. 제안서의 모든 기능(MILDO Board · Watch · Lab · Alert · Flow + AI 엔진 5종: Pro-board · AD Pilot · GFA Control v1 · VisualTune OS · SearchTuneOS)과 신규 기능(MILDO Agent 등)을 한 툴에 합친다.

원문 텍스트: RFP는 `src/data/constants.ts`의 `RFP`, 제안서 기준값은 같은 파일의 `PROPOSAL` 계열 상수에 장표 번호와 함께 정리되어 있다. **새 상수가 필요하면 모듈 폴더 안의 `data.ts`에 출처(장표 번호)를 주석으로 남겨 정의한다. `src/data/constants.ts`는 수정하지 않는다.**

## 0. 사용자(의사결정자) 원칙 — 모든 화면 · 문구 · AI 출력에 적용

이 툴의 사용자는 대형 광고대행사 영업본부장 출신 시니어 전략가 관점으로 판단한다.

- 판단 기준: **CAC / CPA / ROAS / CVR / 볼륨 / 확장성**. 아이디어 나열 · 트렌드 요약 금지.
- "좋다/나쁘다/성장한다/위험하다" 같은 판정은 **전제 조건 + 수치 기준(또는 볼륨 한계) + 대체 시나리오/반례** 없이 쓰지 않는다. 판정 배지(확대/유지/중단 등)는 반드시 옆에 기준값을 보여준다 (예: "확장 · 목표 ROAS 400% 대비 132%").
- 추정이 들어가면 **확정 팩트 / 반복 관측 패턴 / AI 해석** 세 영역을 분리해 보여준다 (`AiInsight` 컴포넌트와 `Brief` 구조가 이것을 강제한다).
- 마케팅 해석은 CAC 회수 구조, 퍼널 내 역할(유입/전환/리텐션), 단기 성과 vs 중장기 효율, 확장 시 비용 구조 변화로 한다.
- 문구: 번호 매기기 금지(1. 2. 3.), 감정 표현 금지, 단락 문장, 자동 요약 문단 금지. 미팅용 멘트/한 줄 요약은 만들지 않는다.
- 모르면 모른다고 쓴다. 데이터가 TEST DATA면 그렇게 표기한다.

## 1. 데이터 원칙 (제안서 p.60 "실제 작동 화면과 테스트 데이터를 구분해 표기")

- 성과 수치는 `state.data` (`Dataset`, `src/data/demo.ts`가 생성한 **시연용 테스트 데이터**)에서만 읽는다. 화면에 성과 수치를 보여주는 카드에는 `<Src kind="DEMO" />`를 붙인다.
- RFP 값에는 `<Src kind="RFP" />`, 제안서 기준값에는 `<Src kind="PROPOSAL" page="p.44" />`, AI 결과에는 `<Src kind="AI" />`.
- 기준일: `state.data.today` = 2026-10-31(토), `state.data.currentHour` = 15. **`new Date()`로 '오늘'을 정하지 말고 데이터 기준일을 쓴다** (타임스탬프 기록용 `nowIso()`는 허용).
- 데모 데이터에 심어둔 시연 시나리오 (탐지 · 판정 로직이 이것들을 실제로 잡아내야 한다):
  - 오늘 14~15시 **Meta 광고비 급등**(동시간 대비 약 +68%, 전환 −30%) → P2 데이터 급변
  - 오늘 13시 이후 **카카오 전환 0** (클릭은 정상) → 전환 추적 단절 의심 (P1, 자동 조정 보류)
  - **GFA 계정 잔액 235만 < 일 평균 소진 259만** + 자동충전 실패 → P1 계정·결제
  - **Google 계정에 비실명 공유 계정**(agency-shared@, 관리자) → 권한 이슈
  - **오늘의집 계정 status 'review'** (검수/확인 필요)
  - **킹 사이즈 옵션 품절** (`products[0].options` k inStock=false) + '킹 매트리스' 키워드가 상품 상세로 랜딩 → 품절 랜딩
  - **'매트리스 추천' 최근 3일 CPC 급등 · 전환 하락** → AD Pilot 자동 조정 보류 + 원인 후보 '경쟁사 입찰 상승'
  - 캠페인 **SA_일반 제품(페이스 1.32), Meta_넓은 타겟(1.58)** → 일 예산 조기 소진 예상
  - 키워드 profile: star(고효율 · 노출 기회 손실 26~42%) / weak(목표 ROAS 미달) / test(테스트 그룹) / new(첫 독립 매트리스, 최근 14일만 집행)
  - 검색어 보고서 `searchTerms`에 미등록 구문형 후보 다수
  - 프로모션 `promotions` (가을 이사·혼수 기획전 15%, 오늘의집 집들이 위크 12%, 11월 기획전 예정)
  - 브랜드 검색량 `brandSearchDaily`는 GFA 집행에 1~2일 시차로 동행 (DA→SA 분석용)

## 2. 공용 계약 (반드시 사용)

- 상태: `useStore()` → `{ state, dispatch }`, `useActions()` → `toast`, `addChange`, `updateChange`, `addIncident`, `updateIncident` (`src/core/store.tsx`). 승인 흐름은 모두 `ChangeRequest`로 `state.changes`에 남긴다 → MILDO Flow가 한 화면에서 보여준다. `requestedBy`/`by`는 `state.role` 또는 시스템명('AD Pilot', 'MILDO Alert' 등).
- 집계: `src/core/selectors.ts` (`totalsOf`, `mediaRows`, `rangeOf`, `previousRange`, `byMedia`, `dailySeries`, `salesByChannel`, `monthlyPacing`, `campaignPacing`, `keywordMetrics`, `headline`). 같은 숫자는 같은 셀렉터로 계산한다.
- 유틸: `src/core/util.ts` (`fmt.krw/won/pct/roas/delta/int`, `metrics`, `pearson`, `linreg`, `twoProportionZ`, 날짜 함수, `isOffDay`, `KR_HOLIDAYS`, `uid`, `nowIso`).
- UI: `src/ui/primitives.tsx` (`PageHeader`, `Card`, `Stat`, `Delta`, `Pill`, `Src`, `Sev`, `Tabs`, `Segmented`, `Field`, `NumberInput`, `Toggle`, `DataTable`, `Callout`, `ProgressBar`, `Modal`, `Drawer`, `CopyButton`, `DownloadButton`, `Empty`, `Swatch`, `Button`, `IconButton`), `src/ui/charts.tsx` (`LineChart`, `BarChart`, `HBarChart`, `ShareBar`, `Sparkline`, `Heatmap`, `Funnel`, `Gantt`, `Legend`), `src/ui/Icon.tsx`, `src/ui/Markdown.tsx`, `src/ui/AiInsight.tsx`.
- 스타일: `src/styles/app.css` 클래스(`page`, `grid g-2..g-6`, `span-2`, `row`, `row-between`, `stack`, `card`, `tbl` 등)와 CSS 변수만 쓴다. 색을 하드코딩하지 않는다. 매체 색은 `MEDIA[m].colorVar`, 판매 채널은 `SALES_CHANNELS[c].colorVar` (색은 엔티티에 고정, 순위로 바꾸지 않음). 상태색(good/warning/serious/critical)은 시리즈 색으로 쓰지 않고, 항상 아이콘/라벨과 함께 쓴다. 모듈 전용 CSS가 꼭 필요하면 `src/modules/<id>/styles.css`를 만들고 View에서 import (클래스 접두사 `<id>-`).
- AI: `useAi()` (`backend`, `connected`, `ask`, `askJson`), `ANALYST_RULES`, `Brief`, `briefToMarkdown` (`src/ai/*`). **AI가 연결되지 않아도 모든 기능이 규칙 엔진으로 동작해야 한다.** AI는 해석 · 생성 품질을 올리는 계층이다. AI 호출은 버튼 클릭 시에만 (로드 시 자동 호출 금지). 결과에는 `<Src kind="AI" />`.
- 라우팅: `navigate('alert')` (`src/core/router.ts`), 링크는 `<a href="#alert">`.
- 파일 내보내기: `DownloadButton`/`CopyButton` (`src/core/download.ts`). `window.alert/confirm/prompt/print`, `window.open` 사용 금지 (아티팩트 샌드박스에서 막힘). 확인 단계가 필요하면 화면 안 2단계 버튼으로.
- 외부 fetch 금지 (아티팩트 CSP에서 막힘). 외부 링크는 `<a href target="_blank">`.

### 모듈 파일 구조 (각 빌더는 자기 폴더만 수정)

```
src/modules/<id>/
  View.tsx       # default export 화면 (탭 구성 가능)
  engine.ts      # 순수 함수 (판정 · 탐지 · 계산). React import 금지.
  engine.test.ts # vitest — 판정 규칙 · 경계값 · 데모 시나리오 탐지 검증
  agent.ts       # export const agentKit: ModuleAgentKit  (tools + 오프라인 briefs)
  data.ts        # (선택) 모듈 전용 시드 데이터 · 상수 (출처 주석)
  *.tsx          # (선택) 하위 컴포넌트
```

`agent.ts`의 `tools(ctx)`는 MILDO Agent가 Claude tool use로 부르는 함수다. 이름은 `<id>_<동사>` (예: `alert_scan`, `adpilot_proposals`), 설명은 무엇을 반환하는지 1~2문장, 결과는 작은 plain JSON(32KB 이하, 숫자는 반올림). 상태를 바꾸는 도구(승인 요청 생성 등)는 `ChangeRequest`를 `pending`으로만 만들고 실제 반영은 사람이 승인하게 한다. `briefs`는 AI 미연결 시 질문을 정규식으로 매칭해 `Brief`(facts/patterns/interpretation/conditions/counter/actions)를 만드는 규칙 기반 답변이다. 각 모듈 최소 도구 2개 · 브리프 2개.

## 3. 디자인 방향

제안서 시각 체계: 웜 오프화이트 지면, 잉크 블랙 패널(`Card tone="dark"`), 핫핑크 포인트(`--accent`, 남용 금지 — 화면당 핵심 1~2곳), 장표 상단의 영문 eyebrow (`PageHeader eyebrow="05 OPERATIONAL STABILITY"`). 대시보드는 읽는 문서가 아니라 스캔하는 도구: 요약 → 상세 순서, 상태는 배지/스트라이프로 형태화, 표는 숫자 우측 정렬 + tabular-nums. 첫 화면에 의미 있는 상태가 다 보여야 한다 (빈 껍데기 금지). 반응형: 900px 이하 1열.

## 4. 모듈별 요구사항

### board — MILDO Board (Pro-board) · 제안서 p.12–13, p.9
- 통합 데이터 아키텍처 요약(p.12): 광고 매체(네이버 SA·DA · 카카오 · 구글 · 메타) + 판매 채널(브랜드스토어 · 오늘의집 · 쿠팡 · 자사몰) + 외부 데이터 → 날짜 · 채널 · 키워드 · 상품 키 표준화 → 광고비 대비 채널별 실매출. 데이터 수집 상태(최근 수집 07:00 완료 등) 표시.
- 기간 선택(어제/최근 7/14/30일/이번 달), 직전 기간 대비 증감.
- KPI: 광고비, 광고 매출(ROAS), 판매 채널 실매출(광고 외 포함) 및 **광고비 대비 실매출(MER)**, CPA, CVR, 신규 고객 CAC.
- ① 매체 통합 성과: 6개 매체를 동일 기준(광고비 · 매출 · ROAS · CPA · CVR · 신규 비중 · 비중)으로 비교 테이블 + 매체별 역할/판단 지표(p.37) 병기 + 일자별 추이(라인, 매체 선택).
- ② 키워드 성과 필터: 구매 의도(브랜드 방어/일반 제품/문제 해결/비교·검토/생활 상황) · 상태(on/test) · 검색어 필터, 키워드별 14일 성과 + 스파크라인 + 직전 14일 대비. CSV 내보내기.
- ③ 예산 소진 현황: 월 예산(연 배분/12) 대비 소진율, 기대 소진율 마커, 예상 월말 소진/예상 마감일; 캠페인별 일 예산 소진율 + 예상 마감 시각(`campaignPacing`) — 조기 소진 경고.
- 판매 채널 실매출: 채널별 매출 · 주문 · CVR · 객단가, 광고 경유 비중.
- 시간대 × 요일 히트맵(최근 4주, 광고비 또는 전환).
- `AiInsight`: 기간 성과 해석.
- 도구: `board_summary`(기간 KPI · 매체별), `board_keywords`(필터 조건 → 상위 키워드), `board_pacing`.

### adpilot — AD Pilot 입찰·예산 최적화 + GFA Control v1 · 제안서 p.14–16, p.9
- **AD Pilot 규칙(p.14)**을 `engine.ts`의 `generateBidProposals(data, config)`로 구현 (현재 스텁 시그니처 `generateBidProposals(data: Dataset): BidProposal[]` 유지, config는 선택 두 번째 인자):
  - 고효율 키워드(ROAS ≥ 목표×1.3) + 노출 기회 손실 ≥ 25% → 입찰 상향 (최대 입찰가 내, 일 조정 폭 상한 20%)
  - 목표 ROAS 미달 지속(최근 14일 & 직전 14일 모두 미달) + 최소 전환 확보(≥3) → 입찰 하향
  - 일 예산 조기 소진 예상(campaignPacing earlyExhaust) → 예산 재배분 · 입찰 조정 제안
  - 신규 구매 의도 키워드 발견(검색어 보고서 미등록 + 전환 발생) → 테스트 그룹 등록 후보
  - 성과 급변 · 수집 데이터 이상(최근 3일 CPC/전환 ±50%) → 자동 조정 보류 · 알림
  - 브랜드 키워드 별도 기준(점유 방어: 브랜드 목표 ROAS 800%, 순위 방어 우선)
- SAFETY 패널(블랙): 일 조정 폭 상한 · 브랜드 키워드 별도 기준 · 변경 이력 전체 기록(누가·언제·왜) · 즉시 롤백. 설정값(목표 ROAS, 상한%) 편집 가능.
- 흐름: 조정 후보 → [승인 요청] (`addChange` pending, approver는 변경 폭 기준) → [승인] → [반영] (적용된 입찰가를 로컬 상태로 유지해 테이블에 반영) → [롤백] (직전 입찰 상태로 복원, `rolled_back`). 일괄 승인/반영. 대량 변경 실수 방지: 한 번에 N건 이상 또는 상한 초과 시 경고/차단.
- 키워드 진단 테이블(라이브 데모 03:00–07:00 "키워드 진단 · 신규 후보 발굴 · 자동 입찰 검증"): 키워드별 판정 배지 + 근거(목표 대비 %) + 노출 기회 손실 + 순위.
- 자동 입찰 검증: 입찰 변경 시 예상 효과(클릭/비용/전환 변화)를 탄력성 가정으로 시뮬레이션해 보여주고, 가정임을 표기.
- **GFA Control v1(p.15)**: GFA 다계정(데모로 2~3개 계정 · 캠페인 = `data.campaigns`의 GFA) 예산 · 상태 점검, 변경 요청 폼(일 예산 변경 %, 광고그룹 ON/OFF, 신규 캠페인) → 위임 범위로 승인 주체 자동 라우팅(±10% 이내 AE, ±10~30%·ON/OFF PM, 30% 초과·신규 캠페인 수면밀도 승인 — `GFA_DELEGATION`) → 실행 · 이력. 현재 역할(`state.role`)에 승인 권한이 없으면 승인 버튼 비활성 + 이유 표시.

- 반복 구간 축소 표(p.31, `FLOW_SEGMENTS`): 지금 vs MILDO Flow 이후 vs 효과.

- **프로모션 체크리스트 · 오픈 전 자동 점검**: `data.promotions`별 체크리스트(일정 · 가격 · 소재 · 랜딩 · 예산 · 재고 · 결제 잔액) 자동 점검 — 소재 문구 가격(`adCopyPrice`) vs 판매가×(1−할인율) 대조, 랜딩 상품 옵션 품절, 예산 여유, 계정 잔액. 통과/실패 + 조치.

### alert — MILDO Alert · 제안서 p.43–50, p.10
- **`engine.ts`의 `detectIncidents(data)`를 구현** (Shell이 앱 시작 시 호출. 시그니처 유지, id는 결정적: `${ruleId}:${target}:${today}`). 탐지 규칙:
  - 크리티컬 이슈 6유형(p.44, `CRITICAL_ISSUE_TYPES`): 광고 OFF·미노출(핵심 키워드 노출 0 · 캠페인 중지 · 예산 소진 중지), 계정·결제(잔액 1일치 미만 · 자동충전 실패 · 권한 변경 · 계정 제재), 소재·랜딩(소재 반려 · 검수 보류 · URL 오류 · 품절 페이지), 데이터 급변(동요일 · 동시간 대비 ±50%), 매체·외부 환경(P3), 주말·공휴일(동일 기준 · 당번 AE).
  - 추가 6종(p.45, `EXTRA_DETECTORS`): 전환 추적 단절(전환 0 패턴 → 자동 조정 즉시 보류), 품절·옵션 품절 랜딩, 가격·프로모션 불일치, 브랜드 키워드 침투, 무효 트래픽 급증, 대량 변경 실수(이건 state.changes 기반이라 별도 함수 `detectBulkChange(changes)`).
  - 성과 이상 징후(p.47, `ANOMALY_THRESHOLDS`): 광고비/클릭 동요일·동시간 평균 대비 ±30% 주의 · ±50% 위험, 전환 최근 7일 동시간 대비 −30/−50, CPA 최근 7일 평균 대비 +30/+50, ROAS −20/−35. **기준선 계산은 `mediaHourly`로 실제 수행** (동요일 = 최근 4주 같은 요일 같은 시간 평균). 원인 후보(`CAUSE_CANDIDATES`)를 데이터 근거로 순위화.
  - 데모 시나리오 전부 탐지되어야 함 (§1 목록) — 테스트로 검증.
- 화면: 5단계 안전망(p.43) 헤더 스트립, 열린 이슈 큐(등급 · SLA 타이머(인지 15분/1차 조치 30분/결과 보고 2시간 등 `SLA`) · 담당 AE + 백업 · 상태), 이슈 상세 드로어(감지 근거 수치 · 원인 후보 · 영향(노출 · 광고비 · 추정 매출 손실) · 자동 조치 · 타임라인) + 액션: 인지 → 배정(TF 역할) → 1차 조치(조치 메모) → 결과 보고 → 재발 방지 → 해결. **조치 보고서 양식(p.49, `INCIDENT_REPORT_TEMPLATE`)으로 보고서 자동 생성**(복사/다운로드).
  - 메신저 알림 미리보기(p.46 "자동 알림 실제 화면"): P1/P2 알림을 메신저 카드 형태로(원인 요약 + 다음 조치 포함) 렌더링한 목업 + 메일 형태 P3.
  - **테스트 이슈 주입(라이브 데모 07:00–10:00)**: "광고 OFF", "결제 실패", "광고비 급변", "소재 반려" 버튼 → 테스트 데이터로 이슈 생성(isTest=true, 토스트 알림, 알림 이력에 기록).
  - 탐지 기준 편집(초기값 · 오탐률 보며 조정), 기준 변경은 ChangeRequest(kind 'alert_rule', approver 'PM').
  - 주말·공휴일 대응(p.48): 1차 MILDO Alert 상시 → 2차 당번 AE 30분 내 확인 → 3차 PM 에스컬레이션(P1 한정). 당번 순번표(주말·공휴일 날짜 × TF 역할, `isOffDay` + `KR_HOLIDAYS`), **연휴 전날 사전 점검 체크리스트**(예산 · 소재 · 결제 잔액 — 실제 데이터로 점검 결과 표시). `state.offHoursMode` 토글로 주말 모드 시뮬레이션.

## 5. 품질 기준 (리뷰어가 확인)

- `npx tsc --noEmit` 통과, `npx vitest run src/modules/<id>` 통과.
- 데모 시나리오가 해당 모듈에서 실제로 잡힌다(하드코딩한 결과가 아니라 엔진이 데이터로 판정).
- 모든 판정 배지 옆에 기준값 · 근거 수치. 성과 수치 카드에 TEST DATA 태그.

- 빈 상태 · 0 나누기 · NaN 방어. 콘솔 에러 없음.
- 번호 매기기 · 감정 표현 · 근거 없는 판정 문구 없음.
